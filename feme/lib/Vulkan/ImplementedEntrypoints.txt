# V6: VK_KHR_dynamic_rendering (promoted to core in 1.3; this driver
# implements the KHR-suffixed commands, listed under SUPPORTED_EXTENSIONS
# below, rather than the core names -- see "Render passes and dynamic
# rendering". Unlike VK_KHR_copy_commands2 above, no CTS crash from this
# gap has been observed: `dEQP-VK.renderpasses`/`dynamic_rendering`/
# `pipeline` all still call these through a route that resolves to the
# implemented KHR name, but the core names remain unimplemented and are
# tracked as an open gap by Roadmap.md's D-series rows).
