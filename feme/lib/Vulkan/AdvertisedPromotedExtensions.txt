# Extension names, from vk_gen_feature_inventory.py's inventoried core
# `promotedto` lists (1.1 through 1.4), that this ICD implements -- either
# advertised by name in feme/lib/Vulkan/PhysicalDeviceInfo.cpp's
# getSupportedDeviceExtensions, or reachable only through the promoted core
# VK_VERSION_1_x entry points, which is equally sufficient for the core
# version's own mandatory floor (an application using the core name gets the
# real implementation regardless). Rows of the second kind say so in their
# note, and each must also appear in
# feme/lib/Vulkan/CorePromotedNotAdvertisedExtensions.txt, which is what
# VulkanExtensionInventory.md uses to keep the two states distinct.
#
# Every advertised-by-name row must stay a subset of PhysicalDeviceInfo.cpp's
# own list and of feme/utils/vk_gen_entrypoints.py's SUPPORTED_EXTENSIONS
# (see roadmap D1's audit,
# feme/utils/vk_gen_feature_inventory.py --advertised-extensions).
#
# Promoted extensions this ICD implements only *partially* are deliberately
# absent: a partial implementation is a conformance gap (roadmap 1.9.10's
# K-series), not an entry here.
#
# --- Promoted into Vulkan 1.1, all core-only (never advertised by name).

VK_KHR_descriptor_update_template = core, not advertised by name: descriptor-set update templates (Descriptor.cpp)
VK_KHR_maintenance1 = core, not advertised by name: vkTrimCommandPool (CommandBuffer.cpp)
VK_KHR_maintenance3 = core, not advertised by name: vkGetDescriptorSetLayoutSupport + VkPhysicalDeviceMaintenance3Properties (Descriptor.cpp, EntryPoints.cpp)
VK_KHR_relaxed_block_layout = core, not advertised by name: declared offsets/strides are used as-is, no std140 re-layout is imposed (SPIRVToLLVMPatterns.cpp)
VK_KHR_storage_buffer_storage_class = core, not advertised by name: the StorageBuffer storage class is accepted directly (SPIRVToLLVMPatterns.cpp)
#

VK_KHR_uniform_buffer_standard_layout = core, not advertised by name: roadmap C6, no std140 restriction was ever enforced to relax (EntryPoints.cpp, SPIRVToLLVMPatterns.cpp)
