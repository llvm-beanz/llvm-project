# Extension names that are inside this ICD's declared conformance scope --
# full Vulkan 1.4 including compute, graphics and ray tracing, see
# feme/docs/FeMeVulkanDesign.md's "Conformance Target" -- but are not
# implemented today. Consumed by
# feme/utils/vk_gen_extension_inventory.py --planned, which renders each as
# "Planned (in scope, not implemented)" rather than the bare "Not
# implemented" it shares with every deliberate non-goal.
#
# Membership rule, so this file does not drift into a wish list:
#
#  1. every extension vk.xml records as promoted into core 1.1-1.4 that
#     this ICD does not already implement (a core version's own mandatory
#     floor is inherited by any later version's claim), plus
#  2. the ray-tracing extension set and its dependencies (roadmap 1.9.8),
#     plus
#  3. the graphics/WSI extensions roadmap 1.9.7 assigns, plus
#  4. the large optional extension groups roadmap H12 (1.9.7) decided
#     belong in scope for this effort: VK_EXT_transform_feedback,
#     VK_EXT_shader_object, VK_KHR_fragment_shading_rate,
#     VK_EXT_fragment_shader_interlock, VK_KHR_fragment_shader_barycentric,
#     and VK_EXT_conditional_rendering (each with its own H21-H26 breakdown
#     row). Sparse residency and protected memory were part of that same
#     H12 decision too, but promote core 1.0/1.1 *feature bits*
#     (Vulkan14FeatureInventory.md), not a dedicated extension name, so
#     they are not listed here.
#
# Anything else -- video, device groups, external memory/synchronization,
# cooperative matrix/vector -- is optional for a 1.4 submission and stays
# out of scope (Roadmap.md, Part 4), so it must NOT be listed here.
# A partially-implemented extension belongs here too: partial is a gap,
# not a status.
